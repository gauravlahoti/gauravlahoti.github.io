# Spec: Insights Index

## Overview

The home page renders all 19 LinkedIn posts inline. Measured on localhost at
1440px, `#insights` is 3,851px of an 8,013px page (48%), and it is the last
section, so the footer sits about six screens below the fold. An outside review
suggested cutting it to the best four posts (Gaurav chose five) plus a "View all" link. This spec
does that: the home page shows five hand-picked posts and a "View all N
insights →" link to a new `/insights/` page that holds the full list, the
search box and the tag filters. "Book a 1:1" is out of scope and does not
change anywhere.

## Rules for implementation

- All identity content lives in `content/profile.json`.
- CSS variables only. Never hardcode hex.
- One JS module per visualization; lazy-load on viewport entry.
- No npm, no bundler, no Node toolchain at runtime (the generator script already exists).
- Respect `prefers-reduced-motion`.
- Mobile fallbacks for every WebGL/Three.js feature.
- No em-dashes in copy.
- "Book a 1:1" nav CTA, drawer CTA, hero link, post-page session box and footer link are not touched.

## Definition of done

- [ ] Home `#insights` shows exactly 5 posts (the featured ones) and no search bar or tag chips.
- [ ] A "View all 19 insights →" link under them opens `/insights/`.
- [ ] Home `#insights` section height is under 1,400px at 1440px wide (was 3,851px).
- [ ] `/insights/` lists all posts newest first, with working search, tag filters and metric chips.
- [ ] `/insights/` shows the full list with JS disabled.
- [ ] Nav flyout "View all insights" and post-page "All insights" go to `/insights/`.
- [ ] Nav "Insights" from other pages goes to `/insights/`; on the home page it still scrolls to `#insights`.
- [ ] `/insights/` is in `sitemap.xml`; re-running the generator leaves files byte-identical.
- [ ] Every "Book a 1:1" link is unchanged.
- [ ] Mobile (390px): the 5 rows and the View all link fit without horizontal scroll.
- [ ] No console errors on `/` or `/insights/`.

## Additions from localhost review

- `/insights/` uses the full content width (`--max-w`): post cards in two
  columns from 900px, one column below. Intro and search span the grid.
- Post pages: on screens 1100px and wider, the article keeps its 720px
  measure and a 320px sidebar holds the 1:1 box (text and link unchanged), a
  "More insights" list (featured posts minus the current one, plus "View all"),
  and the Atlas / live agents buttons. The sidebar stays in view while
  scrolling when the window is at least 900px tall. Below 1100px it stacks
  under the article as before.
- "Chat with my agent" on post pages links to `/?chat=1`; `main.js` opens
  Atlas on arrival (source `insight-post`) and strips the param from the URL.
  It used to land on the home page with the chat closed.
- `site-stage.js`: off the home page (post pages, /live-agents/), Atlas's
  home-section targets (top, career, about) open the home page in the stage
  frame instead of firing a scroll nobody listens to, and "insights" opens
  `/insights/`. The stage's close button reads "Close" there. Before this,
  "take me home" on a post page did nothing while Atlas said it had.
