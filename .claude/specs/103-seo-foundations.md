# Spec: SEO Foundations

## Overview
Search engines barely know gauravlahoti.dev exists. A search for the domain returns other people's portfolios. `robots.txt`, `sitemap.xml` and `llms.txt` all return 404, the home `<title>` is just the name, and the Person JSON-LD has a wrong Topmate link and publishes a personal email. This spec ships the crawl foundations, so the manual Search Console and Bing steps (listed below) have something to point at. Promotion and content work come after, in later specs.

## Depends on
- Spec 100 (Selected Work page): it is one of the URLs in the sitemap.
- The insight pages generated by `scripts/gen-post-pages.mjs` (they already carry BlogPosting JSON-LD, so nothing changes there).

## Routes
No backend.

## Database changes
No database.

## Templates
- **Create:** `robots.txt`, `sitemap.xml`, `llms.txt` (repo root, all served by Pages), `scripts/gen-sitemap.mjs`
- **Modify:** `index.html` (title, description, og/twitter titles, Person JSON-LD, plus a WebSite node), `scripts/gen-post-pages.mjs` (regenerates the sitemap at the end of each run)

## Files to change
- `index.html`
  - `<title>`: `Gaurav Lahoti | Cloud & AI Architect, AI agents for enterprise systems`
  - Meta, og and twitter description: name the role and the niche (MCP, agent-ready enterprise systems, Google ADK)
  - Person JSON-LD: Topmate `gaurav_lahoti12` becomes `gaurav_lahoti25` (matches `content/profile.json`), add `knowsAbout`, remove `email`, use the `@graph` form with a `WebSite` node
- `assets/js/main.js`: remove `setTitle()`. It overwrote `document.title` with `name | title` from `profile.json` at runtime, so Google, which runs JavaScript, would have indexed that title instead of the static one.
- `scripts/gen-post-pages.mjs`: run `gen-sitemap.mjs` once the pages are written, so `/add-post` keeps the sitemap current

## Files to create
- `robots.txt`: allow every crawler, including AI search crawlers, and point to the sitemap
- `scripts/gen-sitemap.mjs`: writes `sitemap.xml` with the static pages (home, `/selected-work/`, `/live-agents/`, `/ai-labs/` and the three on-site labs) plus every insight from `content/posts.json` that has a slug and a page on disk, with `<lastmod>` set from the post date. The redirect stubs (`rag-lab`, `agentic-harness`) are left out.
- `sitemap.xml`: generated output, committed
- `llms.txt`: a short hand-written Markdown summary for AI assistants, with links to the best pages. It follows the voice rules (no em-dashes).

## New dependencies
No new dependencies.

## Rules for implementation
- All identity content lives in `content/profile.json`.
- CSS variables only. Never hardcode hex.
- One JS module per visualization; lazy-load on viewport entry.
- No npm, no bundler, no Node toolchain. The generator scripts are plain Node with no dependencies, like the existing `scripts/*.mjs`.
- Respect `prefers-reduced-motion`.
- Mobile fallbacks for every WebGL/Three.js feature.
- No em-dashes in new copy.

## Manual follow-up (owner, after deploy)
1. Google Search Console: verify the domain property with a DNS TXT record, submit `https://gauravlahoti.dev/sitemap.xml`, then use Request indexing on the home page, `/selected-work/` and the top insights.
2. Bing Webmaster Tools: import from GSC, then submit the sitemap. Bing feeds ChatGPT search and Copilot.
3. Link to gauravlahoti.dev from every profile you own: LinkedIn (Contact info and Featured), the GitHub README, Credly, Topmate, YouTube, the hackathon pages and your email signature.
4. Add YouTube and Credly profile URLs to the Person `sameAs` once they're known.

- [ ] The home tab title reads `Gaurav Lahoti | Cloud & AI Architect, ...`
- [ ] The home JSON-LD parses, contains no `email`, and its Topmate URL matches `profile.json`

- [ ] `grep '—' llms.txt` returns nothing
