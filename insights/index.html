Your agent’s small decisions don’t need an LLM A new class of model is emerging in the AI ecosystem and it doesn’t generate text. 𝗦𝘆𝘀𝘁𝗲𝗺 𝗢𝗻𝗲 𝗠𝗼𝗱𝗲𝗹𝘀 LLMs are System Two: slow, deliberate, great at working through a problem. System One models are built for the blink. Give them context and typed questions and they return answers your code can use directly, each with a probability and a confidence score. Nothing to parse. I’ve been reviewing two of them. 𝗝𝗲𝘃 is the flagship System One model from TypeSafe AI. Google launched 𝗚𝗲𝗺𝗶𝗻𝗶 𝗗𝗲𝗰𝗶𝘀𝗶𝗼𝗻 𝟭 on November 11. It takes up to 1,000 questions per request, with 150 to 250 ms end-to-end latency. OpenAI is already in this space too. This is a category now, not a one-off. One nuance: these models can’t return malformed output, but they can still be wrong. That’s why the confidence score matters. High confidence, act. Low confidence, escalate. Where they fit outside chat: → Checking whether an invoice can be paid (escalating edge cases to a human) → Moderating live chat in real time → Catching fabricated citations in LLM answers For agents, the immediate value is in the small decisions made before acting: → Input guardrails: catch prompt injection before the LLM sees it → Model routing: is this query worth a cheap model or a frontier one? → Tool selection: identify which tools will actually help → Skill selection: pick the single relevant capability, or none Each one becomes a typed question answered in milliseconds and the LLM is called only when there is real reasoning to do. I’m building an agent this way and will share the architecture and my findings in my next post. 𝗠𝘆 𝘁𝗮𝗸𝗲: Use System One models for fast, cheap decisions and reserve LLMs like Claude or Gemini for deep reasoning. The harness does everything else: what enters the context window, what persists, which tools can run, who has to approve and what gets checked before you read a word. That hidden layer is where production agents actually break: the wrong context, an unchecked tool call, an answer nobody verified. The seven components you can watch light up: 1. Context management: Deciding what enters the context window and what stays out. Core system instructions stay loaded, while specialized skills load dynamically via progressive disclosure. 2. Planning: Tracking progress via a live checklist. The harness blocks early exit while items remain open. 3. Memory: Pruning and compacting short-term history as the token limit approaches, while fetching persistent facts across user sessions. 4. The agentic loop: Reason, act, observe, repeat. Capped by strict step, token, and cost budgets. 5. Tools and sub-agents: The model emits intent, the harness executes. Sub-agents run inside isolated context windows to avoid context contamination. 6. Self-verification: Testing outputs against schemas, unit tests, or critic models before delivery so the agent can self-correct. 7. Guardrails: Hard permission boundaries, human approval on high-risk actions, and perimeter defense against prompt injection. With the exact same foundation model, a stronger harness is what actually unlocks higher agentic performance. Model intelligence is a rented commodity. Harness engineering is the actual system architecture. Stop waiting for the next frontier model release to fix problems you can solve in your runtime today. A framework is just someone else's harness. Building your own is the fastest way to understand how agents actually work. Underneath, every query resolves through 2 retrieval strategies running in parallel: • Semantic search ranks by cosine similarity over the embeddings, so "neural net" and "deep learning" converge even with no shared tokens. • Lexical search uses BM25 to anchor precision: exact names, rare terms, error codes, the signal pure semantics tends to wash out. The 2 rankings are then merged through Reciprocal Rank Fusion (RRF), which blends both into a single ordered set without either one dominating.
